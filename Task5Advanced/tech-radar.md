# Расширенный технологический радар — «Будущее 2.0»

Четыре кольца зрелости:
- **Adopt** — внедряем как стандарт;
- **Trial** — пилотируем на реальных задачах;
- **Assess** — изучаем, ещё не коммитимся;
- **Hold** — не начинаем новое и выводим существующее.

Радар расширенный: включает архитектурные паттерны наряду с технологиями.

## Квадрант 1 — Архитектурные паттерны и техники

| Элемент | Кольцо | Обоснование |
|---------|--------|-------------|
| Event-Driven Architecture | Adopt | Ядро целевой интеграции — слабая связанность доменов |
| Domain-Driven Design / bounded contexts | Adopt | Основа доменной модели (Task 4) |
| Self-service BI | Adopt | Цель витрины из ТЗ |
| Strangler Fig | Adopt | Стратегия поэтапного вывода легаси |
| Change Data Capture (CDC) | Adopt | Мост DWH → события без переписывания легаси |
| Infrastructure as Code | Adopt | Реализовано в Task 1–2 |
| Data Mesh | Trial | Стратегическое направление, но через пилот — риск незрелости команд (O1) |
| Medallion (Bronze/Silver/Gold) | Trial | Организация данных в lakehouse |
| Saga / process manager | Trial | Согласованность между контекстами при eventual consistency |
| Policy-as-code / федеративное управление | Trial | Дисциплина контрактов событий |
| CQRS | Assess | Полезен точечно (например, для витрин), не массово |
| Монолитный DWH как архитектура | Hold | Заменяется доменной моделью |
| Point-to-point интеграции (ESB-хаб) | Hold | Заменяются событиями |

## Принцип раскладки

Радар различает зрелость **технологии** и зрелость **практики**. Apache Kafka (технология) — Adopt, а Data Mesh (организационный паттерн поверх неё) — Trial: инструмент готов, а операционная модель ещё созревает. Это удерживает от соблазна «внедрить Data Mesh везде сразу» вопреки риску незрелости команд.
